## 🎯 เป้าหมาย

เตรียม AI ให้พร้อมตั้งแต่เช้า เพราะ **บ่ายนี้ (WS3.3) ทุกคนจะใช้ AI ทำฟีเจอร์ของตัวเอง** — และฝึกถือ API Key อย่างปลอดภัยตั้งแต่ครั้งแรก

💡 **API Key คือกุญแจ** — ใครได้ไปก็ใช้โควตาของมหาวิทยาลัยในชื่อเราได้ จึงต้องอยู่ใน Settings ของ Extension เท่านั้น ไม่ลงไฟล์ ไม่ลงแชต ไม่ขึ้นจอ

## 📋 ต้องมีก่อนเริ่ม

- clone repo ทีมแล้วจาก WS1.2 และเปิด VS Code **ที่โฟลเดอร์ของ repo โดยตรง** (`code .` ในโฟลเดอร์ repo)
- ค่า `<BASE_URL>` `<API_KEY>` `<MODEL_ID>` ที่ผู้สอนแจก (กระดาษ/ข้อความส่วนตัว — ไม่ฉายบนจอ)

## 👉 ขั้นตอน

### ขั้นที่ 1 — ติดตั้ง Extension (ถ้ายังไม่มี)

VS Code → Extensions (`Ctrl+Shift+X`) → ค้นหาและ Install:

- **Cline**
- **Kilo Code**

✅ **ต้องเห็น:** ไอคอนของทั้งสองตัวในแถบซ้าย

### ขั้นที่ 2 — ทดสอบ API Key ก่อนใส่ใน Extension (2 นาที)

ทดสอบใน Terminal ว่า Key ใช้ได้ — **พิมพ์ Key ในคำสั่งนี้ครั้งเดียว แล้วล้างประวัติ** (ผู้สอนอาจสาธิตแทน)

**Git Bash / macOS:**

```bash
curl -s <BASE_URL>/models -H "Authorization: Bearer <API_KEY>" | head -c 300
```

**PowerShell:**

```powershell
curl.exe -s <BASE_URL>/models -H "Authorization: Bearer <API_KEY>"
```

✅ **ต้องเห็น:** ข้อความ JSON ที่มีชื่อ `<MODEL_ID>` อยู่ข้างใน

🔧 `401` = Key ผิด · `404` = Base URL ผิด (มักต้องลงท้าย `/v1`) · ไม่ตอบ = เครือข่ายถูกบล็อก → แจ้ง TA

### ขั้นที่ 3 — ตั้งค่า Cline

1. คลิกไอคอน **Cline** → ไอคอนเฟือง ⚙
2. **API Provider** → **OpenAI Compatible**
3. กรอก **Base URL** · **API Key** · **Model ID** → **Done**

### ขั้นที่ 4 — ตั้งค่า Kilo Code

1. คลิกไอคอน **Kilo Code** → ⚙ → **Providers**
2. เลือก **OpenAI Compatible** แล้วกรอกค่าชุดเดียวกัน → บันทึก

### ขั้นที่ 5 — ปิด Auto-approve และเริ่มที่ Plan (สำคัญที่สุด)

- **Cline:** แถบ *Auto-approve* ใต้ช่องพิมพ์ — **ไม่ติ๊กทุกข้อ** · สวิตช์ **Plan / Act** อยู่ที่ **Plan**
- **Kilo Code:** Settings → *Auto-Approve* → ปิดทุกข้อ

💡 ถ้าเปิด Auto-approve AI จะแก้ไฟล์และรันคำสั่งเองทั้งหมด — **"อ่านก่อนกด" คือทักษะที่เราฝึกทั้ง 2 วัน**

### ขั้นที่ 6 — ทดสอบกับ repo ของทีม

ใน **Cline** (Plan) เริ่ม Task ใหม่ แล้วพิมพ์:

```text
อ่าน AGENTS.md แล้วสรุปเป็นข้อ ๆ ว่า 1) โปรเจกต์นี้ใช้ stack อะไร 2) ไฟล์ร่วมที่ห้ามแก้มีอะไรบ้าง 3) คำว่า "เสร็จ" ของโปรเจกต์นี้คืออะไร — ห้ามแก้ไฟล์ใด ๆ
```

✅ **ต้องเห็น:**

- Cline ขออ่านไฟล์ `AGENTS.md` ก่อนตอบ (เห็นเป็นขั้น *Read file*)
- คำตอบตรงกับเนื้อหาใน `AGENTS.md` และไม่มีการขอแก้ไฟล์

จากนั้นพิมพ์ `/` ในช่องพิมพ์ของ Cline

✅ **ต้องเห็น:** `check-before-pr.md` · `deploy.md` · `new-spec.md` ในหมวด Workflows

### ขั้นที่ 7 — ตรวจว่า Key ไม่หลุดเข้า repo

```bash
git status
```

✅ **ต้องเห็น:** ไม่มีไฟล์ใหม่ที่มี Key (Key อยู่ใน Settings ของ Extension ไม่ใช่ในโฟลเดอร์ repo)

## 🔧 ถ้าไม่เป็นแบบนี้

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `401` / `404` ใน Extension | Key / Base URL / Model ID ผิด | ตรวจการคัดลอก (ไม่มีช่องว่างหน้า-หลัง) และ `/v1` |
| `429` | เกิน rate limit | รอ 1 นาที |
| Cline ไม่อ่าน `AGENTS.md` | เปิด VS Code ผิดชั้นโฟลเดอร์ | File → Open Folder → เลือกโฟลเดอร์ repo โดยตรง |
| ไม่เห็น Workflows เมื่อพิมพ์ `/` | ไม่มี `.clinerules/workflows/` ในโฟลเดอร์ที่เปิด หรือ Cline เวอร์ชันเก่า | `git pull` · Reload Window · อัปเดต Cline |
| เผลอวาง Key ในแชต/ไฟล์ | — | แจ้ง TA ทันทีเพื่อ **Revoke** แล้วรับ Key ใหม่ — ไม่ใช่ความผิด แต่ต้องรีบ |
