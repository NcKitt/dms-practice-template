## 1. บริบท — ต่อยอดจากอะไร และทำไมต้องมี

- ประกาศสำคัญ (เช่น ปิดปรับปรุงระบบ) ถูกประกาศใหม่ดันลงไปด้านล่าง
- ต่อยอดจากรายการประกาศ โดยเพิ่มฟิลด์ `pinned` ผ่าน `store.update`
- ฟีเจอร์ stats (E) จะนับจำนวนประกาศที่ปักหมุดจากฟิลด์นี้

## 2. Prerequisites — ต้องพร้อมอะไรก่อนเริ่ม

- [ ] แตก branch `feature/pin` จาก `main` ล่าสุด และ `npm install` แล้ว
- [ ] `npm test` ผ่านก่อนเริ่มแก้ (ถ้าไม่ผ่านตั้งแต่ต้น ให้แจ้งทีม อย่าแก้เอง)
- [ ] อ่าน `AGENTS.md` แล้ว
- [ ] ใช้ชื่อฟิลด์ `pinned` (boolean) ตามที่ตกลงใน `AGENTS.md` / `docs/memory/decisions.md` D-004 — ห้ามตั้งชื่ออื่น

## 3. Contract — สิ่งที่คนอื่นจะพึ่งพา

### API
| Method | Path | Request | Response สำเร็จ | Error |
|---|---|---|---|---|
| POST | `/api/announcements/:id/pin` | ไม่มี body | `200` + ประกาศที่อัปเดต (`pinned` สลับค่า) | `404` ไม่พบ |

### ข้อมูล
| ฟิลด์ | ชนิด | ค่าเริ่มต้นเมื่อไม่มี | เจ้าของ |
|---|---|---|---|
| `pinned` | boolean | `false` | ฟีเจอร์ pin (E อ่าน) |

### หน้าเว็บ
- ปุ่ม **ปักหมุด / เลิกปักหมุด** ในแถบปุ่มของทุกการ์ด (ข้อความเปลี่ยนตามสถานะ)
- การ์ดที่ปักหมุดมีป้าย `📌 ปักหมุด` (ใช้ class `badge`) หน้าหัวข้อ
- ประกาศที่ปักหมุดอยู่บนสุดเสมอ (ใช้ `ctx.addSorter`) ส่วนที่เหลือเรียงตามเดิม

## 5. ข้อกำหนดสำคัญ — กฎที่ห้ามพลาด

- ประกาศที่ยังไม่มีฟิลด์ `pinned` ให้ถือว่า `false`
- บันทึกค่าเป็น boolean จริง (`true`/`false`) ไม่ใช่ string
- แสดงข้อความจากผู้ใช้ด้วย `textContent` เท่านั้น ห้าม `innerHTML`
- error ตอบเป็น `{ "error": "ข้อความภาษาไทย" }` และแปลง id ด้วย `Number(req.params.id)`

## 7. Acceptance Criteria — นิยามของคำว่า "เสร็จ"

รัน `npm run dev` ไว้ในอีก Terminal **(เริ่มใหม่ก่อนตรวจ เพื่อให้ข้อมูลกลับเป็นตัวอย่าง 2 รายการ)** แล้วรันทีละข้อตามลำดับ
— ใน PowerShell ใช้ `curl.exe` หรือรันใน Git Bash

1. กดครั้งแรก → ปักหมุด

   ```bash
   curl -s -X POST localhost:3000/api/announcements/2/pin
   ```
   ต้องเห็น: `"pinned":true`

2. กดอีกครั้ง → เลิกปักหมุด

   ```bash
   curl -s -X POST localhost:3000/api/announcements/2/pin
   ```
   ต้องเห็น: `"pinned":false`

3. ไม่พบประกาศ → 404

   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" -X POST localhost:3000/api/announcements/9999/pin
   ```
   ต้องเห็น: `404`

4. test ของฟีเจอร์ผ่าน

   ```bash
   node --test test/pin.test.js
   ```
   ต้องเห็น: `fail 0`

5. ตรวจบนหน้าเว็บ (ดูด้วยตา): กด **ปักหมุด** ที่การ์ดล่างสุด → การ์ดขึ้นไปบนสุดพร้อมป้าย 📌 · กด **เลิกปักหมุด** → กลับที่เดิม

6. ตรวจคุณภาพและขอบเขต

   ```bash
   npm run lint
   npm test
   git diff --name-only main...HEAD
   ```
   ต้องเห็น: `lint ผ่าน` · `fail 0` · รายชื่อไฟล์มีเฉพาะ `src/features/pin.js` `public/features/pin.js` `test/pin.test.js`
