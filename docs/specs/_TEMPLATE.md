## 1. บริบท — ต่อยอดจากอะไร และทำไมต้องมี

- ปัญหา/ความต้องการของผู้ใช้ (1–3 บรรทัด)
- ต่อยอดจากส่วนไหนของระบบที่มีอยู่
- ถ้าไม่ทำจะเกิดอะไร

## 2. Prerequisites — ต้องพร้อมอะไรก่อนเริ่ม

- [ ] แตก branch `feature/<name>` จาก `main` ล่าสุด และ `npm install` แล้ว
- [ ] `npm test` ผ่านก่อนเริ่มแก้ (ถ้าไม่ผ่านตั้งแต่ต้น ให้แจ้งทีม อย่าแก้เอง)
- [ ] (ถ้ามี) ฟีเจอร์/ค่าตั้งค่า/ข้อตกลงที่ต้องมีก่อน

## 5. ข้อกำหนดสำคัญ — กฎที่ห้ามพลาด

- ความปลอดภัย (การตรวจข้อมูล, XSS, ความลับ, สิทธิ์)
- ความถูกต้องของข้อมูล / ลำดับการทำงาน
- ข้อตกลงกับฟีเจอร์อื่น

## 6. ห้ามทำเกินสโคป — นิยามของคำว่า "พอ"

- ห้ามแก้ไฟล์นอกตารางหัวข้อ 4
- ห้ามติดตั้ง package ใหม่
- ห้าม refactor / จัด format ไฟล์อื่น
- สิ่งที่ "ยังไม่ทำในรอบนี้": ...

## 7. Acceptance Criteria — นิยามของคำว่า "เสร็จ"

ทุกข้อต้อง **รันคำสั่งได้จริง และระบุผลที่ต้องเห็น** (รันด้วย `npm run dev` ในอีก Terminal)

1. ...

   ```bash
   <คำสั่ง>
   ```
   ต้องเห็น: `<ผลลัพธ์>`

- [ ] `npm run lint` → `lint ผ่าน`
- [ ] `npm test` → `fail 0` และมี test ใหม่ใน `test/<name>.test.js`
- [ ] `git diff --name-only main...HEAD` → เห็นเฉพาะไฟล์ในหัวข้อ 4

## 8. คำถามที่ยังเปิด

- ถ้า AI หรือผู้พัฒนาเจอกรณีที่ spec ไม่ครอบคลุม → **หยุดและถาม** แล้วบันทึกคำตอบที่นี่
- ตัดสินแล้ว: (คำถาม → คำตอบ)
